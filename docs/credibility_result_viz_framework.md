# Credibility Backtest Visualization Framework

> 用途：主跑次（默认 `DATA2-KO-MARCH`）完成后，从归档抽取、作图、写入 `multi_agent_credibility_report.md` 附录。  
> 状态：设计已定；`DATA2-KO-MARCH` 实证图已生成于 `docs/figures/credibility_ko_march/`，并写入 `multi_agent_credibility_report.md` 附录 B。  
> 原则：图要好看，更要有意义；少而精，宁缺毋滥；每张图必须能用一句话说清“说明了可信度层的什么价值”。

---

## 1. 目标

本框架同时服务报告附录与验收阅读：让人在不打开 SQLite 的情况下，看懂审计层在真实回测里留下了什么、发现了什么。图表优先表达三类信息——**记录是否完整、问题能否分类、单日能否追问到位**——而不是把可信度包装成超额收益故事。

---

## 2. 默认交付包（先定裁剪，再谈愿望清单）

主报告附录默认只收 **6 图 + 2 表**。其余为候补：数据漂亮再加，数据嘈杂则不加。

| 编号 | 名称 | 优先级 | 对应问题 |
|------|------|--------|----------|
| Fig-1 | 净值与审计状态总览 | 必做 | 交易结果与审计标签并行 |
| Fig-2 | 审计状态构成 | 必做 | 不是“全绿才算成功” |
| Fig-3 | 证据覆盖随时间变化 | 必做 | 引用纪律并不自动稳定 |
| Fig-4 | Findings 类型结构 | 必做 | 把不安落实成问题类别 |
| Fig-5 | 七维指标分布 | 必做 | 用多维画像替代总分 |
| Fig-6 | 单日深潜 | 必做 | 故事锚点：一天如何被追问 |
| Table-A | 跑次摘要 | 必做 | 可引用的数字源 |
| Table-B | 主样例日解读 | 必做 | 配合 Fig-6 给不会读图的人 |
| Fig-7 | 评级与仓位路径 | 候补 | 仅当仓位变化足够丰富时 |
| Fig-8 | 主张类型与核验状态 | 候补 | 仅当 claims 字段较完整时 |
| Fig-9 | 记忆溯源对齐 | 候补 | 仅当 provenance 覆盖清晰时 |
| Fig-C | 二月 vs 三月注记 | 默认不做 | 仅当需要区分 API 噪声与审计检出 |

若必做图中有一张在数据上失真（例如几乎全日无画像），应删图并在附录用文字说明，而不是硬画空图。

## 3. 数据源与抽取

### 3.1 权威来源（按优先级）

1. **`runs.result_json`**（跑次完成后）：决策、执行、权益、基准、metrics。这是作图主源。  
2. **`decisions[*].diagnostics`**：审计画像、findings、claims、辩论轮次、记忆溯源、结构化调用记录。  
3. **`run_events`**：核对决策日是否齐全；标出失败保仓日时间线。  
4. **日志 / 记忆库**（抽查用）：不作为主图数据源，只在摘要表或脚注里做对齐说明。

### 3.2 先物化逻辑表，再绘图

避免在绑图代码里反复解析嵌套 JSON。

**run_summary（一行）**  
跑次标签与短码、窗口、决策日数、SUCCESS / FAILED_SAFE 计数、总收益与买入持有收益、费用、换手、最大回撤、有画像天数、三类审计状态计数、证据覆盖的均值与分位数、结构化完整性均值、CRITICAL finding 总数。

**daily_decision（一日一行）**  
日期、决策状态、评级、目标/实现仓位、费用；是否有画像；画像状态与审计范围；七维指标；按严重度计的 finding 数；主张条数；完整辩论周期数；记忆溯源条数。

**finding_long（一条一行）**  
日期、规则代码、严重度、阶段、可选 claim 标识、一句话中文摘要（由代码映射，不直接贴模型长文）。

**equity_panel（一日一行）**  
日期、策略权益、基准权益，并另存归一化净值（起点=1）。日期对齐以投资组合历史为准；决策日若缺行，审计色带记“无决策/无画像”，不得前向填充成“通过”。

**claim_long（候补）**  
仅当 Fig-8 启用时抽取：类型、重要性、核验状态、是否带证据引用。

### 3.3 缺失与口径（硬规则）

- 失败保仓日无画像是预期行为：指标为 NA，禁止填 0。  
- 统计审计分布、七维分布、证据覆盖均值时，分母默认是 **SUCCESS 且有画像** 的日子；另文报告“画像覆盖率 = 有画像天数 / SUCCESS 天数”。  
- 事后重算类证据不得写入“运行时证据充分”的叙事。  
- Findings 展示用中文标签；代码名可放括号，避免验收方只看见一串枚举。

### 3.4 Findings 代码 → 中文释义（作图与表共用）

| 代码（常见） | 中文含义 | 展示优先级 |
|--------------|----------|------------|
| UNSOURCED_CLAIM | 主张未挂到可定位证据 | 高 |
| NUMERIC_EVIDENCE_UNREADABLE | 数值证据字段无法按引用读取 | 高 |
| NUMERIC_EVIDENCE_MISMATCH | 正文数值与证据字段不一致 | 最高（CRITICAL） |
| TOOL_LOOKAHEAD / 时间类 | 工具日期可能越过决策时点 | 高 |
| 其他 WARNING | 合并为“其他告警”或按频次进 Top-N | 中 |

未列入上表的代码：频次高则进入 Top-N 并临时补中文；频次低可归入“其他”。

## 4. 分析问题 → 用图映射

| 要回答的问题 | 主要图表 | 一句话验收标准 |
|--------------|----------|----------------|
| 归档里有没有可信度结果？ | Table-A，必要时脚注记忆对齐 | SUCCESS 日画像覆盖率可报告 |
| 审计在发现什么？ | Fig-2、Fig-4 | 状态与问题类型可分类，而非只有“感觉不可信” |
| 引用纪律稳不稳？ | Fig-3、Fig-5 | 覆盖率与多维指标有分布、有波动 |
| 单日能不能追问？ | Fig-6、Table-B | 能指出状态、关键指标与代表问题 |
| 和交易怎么并列？ | Fig-1（+ 候补 Fig-7） | 两套信息同窗可见，但不宣称因果 |

## 5. 主样例日怎么选

先自动粗排，再人工定 1 个主样例（Fig-6 / Table-B）；如需展示“检出能力”，最多再加 1 个对比日，且必须在图注写明用途不同。

**自动粗排（设计口径，非实现）**

在 SUCCESS 且有画像的日子上计算：

- 结构化健康：当日结构化调用几乎全为成功模式 → 加分  
- 可叙事性：证据覆盖落在大约 0.2–0.8（过低像没接上，过高且零 finding 往往故事性弱）→ 加分  
- 可解释 findings：存在可映射中文的高优先级 finding → 加分  
- CRITICAL 日：适合作为“检出样例”，默认不当唯一主展示，除非全窗只有这类日子可读  

最终主样例应能支撑一段 150–250 字的附录叙述：当天评了什么级、审计什么状态、最值得看的两类问题是什么。

## 6. 各图规格

统一视觉：浅色背景、克制配色、中文标题与图注；审计三态建议蓝 / 琥珀 / 红褐（色盲友好，避免只靠红绿）；禁止霓虹紫、重 glow、3D、爆炸饼图。文件名建议 `fig_cred_ko_mar_01_overview.png` 这类有序命名。

每张图注固定三句结构：**看什么 → 看到什么 → 不要过度解读什么**；页脚含 run 短码、窗口、样本过滤条件。

### Fig-1 净值与审计状态总览（必做）

上屏：策略与买入持有的归一化净值。  
下屏：逐日审计状态色带（通过 / 建议改进 / 需复核 / 无画像）。  
意义：交易结果与材料标签并行。  
禁忌：不用色带“解释”盈亏；若下屏大片无画像，改在文中说明记录缺口，而不是假装连续。

### Fig-2 审计状态构成（必做）

优先用简单柱状或堆叠条，不优先甜甜圈。  
内容：有画像日中三类状态计数；可附审计范围（完整 / 部分）占比。  
意义：诚实展示 DEGRADED 也是系统在工作。

### Fig-3 证据覆盖时间序列（必做）

折线为主，可加短窗平滑；可选次轴画当日主张条数。  
意义：覆盖率波动本身就是审计层存在的理由。  
口径：无画像日记缺测，不连成假连续。

### Fig-4 Findings 类型结构（必做）

水平条形，按中文类别聚合 Top-N；CRITICAL 单独颜色。  
意义：改进方向可指认（未溯源、数值冲突等）。  
若 CRITICAL 为 0，仍保留 WARNING 结构，并在图注写明“本窗未出现致命数值冲突”。

### Fig-5 七维指标分布（必做）

默认箱线或分面条形，二选一；不与小提琴叠床架屋。  
样本：SUCCESS 且有画像；分母为 0 的指标按 NA 剔除并在注记说明。  
意义：多维披露，拒绝单一可信分数。

### Fig-6 单日深潜（必做）

默认平行条形展示七维（雷达可选，因坐标等距易误导）。  
旁侧或下方放 3–5 条 findings 中文释义。  
意义：附录故事锚点。

### Fig-7 评级与仓位（候补）

仅当目标仓位并非长期恒定空仓/单值时启用。  
可与 Fig-1 对照阅读，只写观察、不写因果。

### Fig-8 / Fig-9（候补）

主张构成、记忆对齐：字段质量不足时宁可不画，改用 Table-A 一行文字交代。

## 7. 表规格

**Table-A 跑次摘要**  
窗口、决策日、成功/保仓、策略收益与买入持有、画像覆盖率、三类审计计数、证据覆盖均值、CRITICAL 总数、费用与最大回撤（后两项一笔带过即可）。

**Table-B 主样例日**  
日期、评级、目标仓位、审计状态与范围、三项最能说明问题的指标、两条代表 findings（中文）。

## 8. 明确不做

- LLM 自报置信度的“校准曲线”（无人工复核标签）  
- 审计指标对未来收益的回归主图  
- 超过默认包的 dashboard 堆砌  
- 大段模型原文、未脱敏参数、记忆正文  
- 无过滤条件的全市场对比（本框架先服务单跑次深描）

## 9. 附录叙述顺序（出图后照此写）

建议标题：`附录 B：KO 2024-03 窗实证速写`（随最终跑次微调）。

1. 跑次一句话（标的、窗口、引擎、决策日数）  
2. 记录完整性（Table-A）  
3. 审计发现了什么（Fig-2、Fig-4）  
4. 覆盖与多维画像（Fig-3、Fig-5）  
5. 单日如何被追问（Fig-6、Table-B）  
6. 与交易结果并列（Fig-1，候补 Fig-7）  
7. 限度与未美化之处（保仓日、低覆盖、无 CRITICAL 等如实写）

正文第五节仅加一小段交叉引用，不把附录图全部塞进正文。

---

## 10. 落地前质量门禁

在画第一张图之前检查：

1. 跑次状态为 COMPLETED，且 `result_json` 含完整 decisions / equity。  
2. SUCCESS 日画像覆盖率可计算；若低于约 50%，先改写附录策略为“记录缺口分析”，再决定是否还出 Fig-5/6。  
3. Findings 至少能映射出两类中文类别，否则 Fig-4 改为表。  
4. 主样例日已按 §5 选定，并写好 150–250 字预叙述。  
5. 每张拟入库的图都能通过一句话验收；答不上来的删掉。

---

## 11. 实现触发与工作流

触发条件：你告知三月窗（或指定 run_id）已完成。  

顺序：确认归档 → 物化逻辑表 → 选主样例日 → 出默认 6 图 2 表 → 视数据启用候补 → 写入报告附录 → 按 §10 自检删图。  

工具选择留到实现阶段；优先静态 PNG/SVG，便于 Markdown 嵌入。二月窗默认不进主图；仅当需要区分“接口失败”与“审计检出”时，才考虑单张 Fig-C。
